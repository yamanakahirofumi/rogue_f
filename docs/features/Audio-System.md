# Audio-System

## 1. 概要
オーディオ＆BGMシステムは、RogueFにおける臨場感、緊迫感、および没入感を向上させるためのサウンド管理の仕組みです。
プレイヤーの現在の状況（滞在エリア、バイオーム、遭遇するイベント、および自身のステータス状態）に応じて動的にBGMを遷移させ、また、距離に応じた効果音（SE）の減衰や同時再生数の制限を適切に行うことで、快適かつ臨場感あふれる音響体験を提供します。

## 2. 音量設定の保持
プレイヤーの音量設定（Volume Configuration）は、プレイヤーのメタデータおよびセーブデータ（[セーブ・ロードシステム](Save-Load-System.md)）の一部として永続化されます。

### 2.1 音量パラメータ
プレイヤーは設定画面から、以下の3つの音量カテゴリを独立して調整可能です。それぞれの値は **0 〜 100**（パーセンテージ）の範囲で設定され、実際の再生時には浮動小数点数（`0.0 〜 1.0`）に変換されます。

- **マスター音量 (Master Volume)**: ゲーム全体の最終的な音量を決定します。デフォルト値：`80`
- **BGM音量 (BGM Volume)**: バックグラウンドミュージック（背景音楽）の音量を決定します。デフォルト値：`70`
- **SE音量 (SE Volume)**: 効果音（移動、攻撃、アイテム使用、レベルアップ等）の音量を決定します。デフォルト値：`90`

### 2.2 データ構造への追加
音量設定は、プレイヤーのセーブデータまたはシステム設定データ構造に以下のように組み込まれます。

```typescript
interface AudioSettings {
  masterVolume: number; // 0 ~ 100
  bgmVolume: number;    // 0 ~ 100
  seVolume: number;     // 0 ~ 100
}
```

## 3. 動的BGM遷移ロジック
ゲーム内の状況やエリア変化、重大なイベント、プレイヤーの危機状況に応じて、BGMは動的かつシームレスに切り替わります。

### 3.1 エリア遷移 (拠点 vs ダンジョン)
プレイヤーの滞在する場所の性質により、基本BGMのテーマが変化します。
- **拠点（Town）**: [拠点システム](Base-System.md)にて滞在している間は、平和で落ち着いた街のテーマBGMが再生されます。
- **ダンジョン（Dungeon）**: ダンジョン内部に入ると、探索用の緊迫したBGMへと切り替わります。

### 3.2 バイオーム別BGM
ダンジョン内では、現在の階層の[バイオーム・環境システム](Biome-System.md)に基づき、視覚テーマに連動した個別のBGMが再生されます。

| バイオームID | BGMテーマ | 特徴・雰囲気 |
| :--- | :--- | :--- |
| `cave` (洞窟) | 洞窟のこだま (Cave Echoes) | 暗く静寂で、滴る水の音を基調とした標準的な探索曲。 |
| `forest` (森林) | 木漏れ日のざわめき (Forest Whisper) | 鬱蒼とした緑と風に揺れる木々を想起させる神秘的なテンポの曲。 |
| `ice` (氷雪) | 永久凍土の祈り (Frozen Silence) | 氷のきらめきと孤独感、冷たさを感じさせる静かで澄んだ曲。 |
| `lava` (溶岩) | 灼熱の狂宴 (Volcanic Rage) | 湧き上がるマグマと危険を象徴する、ドラムを基調とした激しくアップテンポな曲。 |

### 3.3 PK乱入時の割り込みBGM
PK（プレイヤーキラー）がダンジョン内に乱入（[PKシステム](PK-System.md)）し、プレイヤーの索敵範囲、または同一階層に存在する場合、探索BGMは即座に**緊迫した「対人・乱入バトル専用BGM」**（PK Intervention Theme）へと切り替わります。
- PKerが撃破されるか、プレイヤーがフロアを移動する、もしくはPKerが帰還するまでこの専用BGMが維持されます。

### 3.4 危機状態（ピンチ）による動的BGM変調
プレイヤーが極限状態に陥った際、生存への焦燥感と緊張感を煽るため、BGMが「危機状態専用BGM」にシームレスに遷移するか、あるいはテンポが早くなる（ピッチアップ）、こもった音（ローパスフィルタ適用）になるなどの動的エフェクトが適用されます。

- **発動条件**:
  - **低HP状態**: プレイヤーの現在HPが最大HPの **20% 以下** に低下した場合。
  - **飢餓状態**: プレイヤーの満腹度（Satiety）が **0** になり、[満腹度システム](Hunger-System.md)によるHP減少ダメージが開始された場合。
- **解除条件**: HPが 20% を超え、かつ満腹度（Satiety）が 1 以上に回復した場合、即座に通常のバイオームBGM（またはPKバトルBGM）に戻ります。

## 4. 効果音（SE）の空間音響（減衰）
ダンジョン内において、プレイヤー以外のエンティティ（モンスター、トラップ、PKer等）が発した効果音は、プレイヤーとの物理的距離に基づいて動的に音量が減衰（空間音響シミュレーション）されます。これにより、視界外での出来事の距離感や方向性を音で察知することが可能になります。

### 4.1 距離減衰式
効果音の音量は、音源からプレイヤーへのタイル距離（チェビシェフ距離またはユークリッド距離）に基づいて以下の計算式で決定されます。

$$\text{最終SE音量} = \text{基本設定音量} \times \text{音源ボリューム（個体）} \times \text{減衰係数}$$

減衰係数（Attenuation Coefficient）は距離 $d$ に応じて以下のように定義されます。

- $d \le 1$（隣接または同一タイル）: **1.0 (等倍再生)**
- $2 \le d \le 6$: **$1.0 - 0.15 \times (d - 1)$**（距離が1増えるごとに15%減衰）
- $d \ge 7$: **0.0 (消音、再生スキップ)**

※プレイヤーの視界外かつ聞こえる範囲（距離2〜6）での戦闘音やトラップ作動音は、かすかに聞こえることで周囲の危険を察知するゲーム性を提供します。

## 5. SE同時再生制限（リミッター）
激しい戦闘中や、多数のトラップが連鎖して発動した際、特定の効果音（例：攻撃音、足音、爆発音など）が同一フレームまたは極めて短い時間内に過剰に重複再生されると、不快な音割れや音量破綻（クリッピング）が発生します。これを防ぐため、**同時再生制限（Concurrency Limiter）**を実装します。

- **同一効果音の最大同時再生数**: 同一のSE（例：`slash_se`）は、**最大 3 回まで**同時に重ねて再生することができます。
- **制御ロジック**:
  - 各SEについて「現在再生中の数」を管理します。
  - 4つ目の同一SEの再生リクエストが発生した場合、以下のいずれかの処理を行います。
    1. 最も再生開始時刻が古い（残り再生時間の短い）同種SEを即座に破棄し、新しいSEを再生する（キュー上書き方式）。
    2. 新規の再生要求を無視する（スキップ方式）。
  - 本システムでは、プレイヤーに最新の操作音をフィードバックするため、**「キュー上書き方式」**を標準として採用します。
