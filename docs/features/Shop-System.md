# Shop-System

## 1. 概要
ショップシステムは、管理者が自身のダンジョン内にアイテム屋を設置・運営し、プレイヤーとアイテムの売買を行うための仕組みです。世界（サーバー）内の流通量に基づいた動的な価格決定と、管理者の戦略的な価格設定を特徴とします。

## 2. ショップの種類

### 2.1 管理者ショップ (Admin Shop)
- 管理者が自身の所持品から商品を選択し、価格を設定して公開する店舗です。
- 管理者のダンジョン内に設置されます。

### 2.2 システムショップ (System Shop)
- ランダムダンジョン内に稀に出現する、自動生成されたショップです。
- **商品の選定ロジック**: 階層の深さ（[ドロップ品・出現システム](Loot-and-Spawn-System.md) 参照）に応じた Tier のアイテムが、抽選で **3 〜 6 スロット** 分陳列されます。
- **価格**: 基本市場価格に基づいた標準的な価格でアイテムを販売します。

## 3. ショップ運営のメカニズム

### 3.1 商品の選定
- 管理者は自身の「ストック（[倉庫システム](Warehouse-System.md)）」から、ショップに陳列するアイテムを選択します。
- 一度に陳列できるアイテム数には上限があります（10 スロット）。

### 3.2 価格決定
- **基本市場価格 (Base Market Price)**: 世界全体の流通量（在庫数）に応じて自動計算される理論上の価格です。
  - 流通が少ないアイテムは高く、多いアイテムは安くなります。
  - **計算式**:
    - `基本市場価格 = 基本価格 * (1 + (サーキュレーション制限 / (現在の流通数 + 1)) * 0.1)`
- **販売価格の設定**: 管理者は基本市場価格を参考に、任意の価格（基本価格の 70% 〜 300%）を設定できます。

### 3.3 販売と収益
- プレイヤーがアイテムを購入すると、代金（ゴールド）は管理者の所持金に加算されます。
- 購入されたアイテムは管理者の在庫から差し引かれます。

## 4. プレイヤーの操作
- **購入**: ショップ内のアイテムを選択し、表示された価格を支払って取得します。
- **売却**: 自身のインベントリ内のアイテムをショップ（または店主）に提示し、提示された買取価格で売却します。
  - 買取価格は基本市場価格の **40%** をベースに算出されます。
  - **買取資金のソース**: アイテムの買い取りに必要なゴールドは、**管理者の個人資産（所持金）から直接支払われます。** 管理者の所持金が買取価格に満たない場合、売却（買い取り）は失敗し、実行することができません。
  - **アイテム状態による補正**:
    - **未識別 (Unidentified)**: 買取価格が **50%**（ベースの 20% 相当）に低下します。
    - **呪い (Cursed)**: 買取価格が **10%**（ベースの 4% 相当）に低下します。
    - **祝福 (Blessed)**: 買取価格が **150%**（ベースの 60% 相当）に上昇します。
    - **補正の累積**: 複数の状態（例：祝福かつ未識別）が重なる場合、それぞれの補正倍率は**乗算（Multiplicative）**で計算されます。
- **鑑定**: 店主に対し、未識別アイテムの鑑定を有料で依頼できます。鑑定料の計算式は「5.2 鑑定料の計算式」を参照してください。詳細は [アイテム識別システム](Item-Identification-System.md) を参照してください。

## 5. カタログ閲覧・鑑定料・自動補充およびイベントログ仕様

### 5.1 ショップカタログ取得 REST API
プレイヤーがマップ上のショップ記号（`$`）に隣接・接触、または拠点ショップを利用する際、画面UI構築のために最新の陳列アイテム一覧、販売価格、残り在庫数、および管理者の買取可能残額を取得します。
- **エンドポイント**: `GET /api/player/{userId}/shop`
- **取得データ構造 (`ShopCatalogResponse`)**:
  - `shopId`: ショップ固有ID
  - `shopName`: 店舗名（例: 「マイクのよろず屋」または「ダンジョン行商」）
  - `shopType`: 店舗カテゴリ (`'admin'` | `'system'`)
  - `ownerGold`: 管理者の所持ゴールド（管理者ショップでのプレイヤー売却時に買い取り可能予算上限。システムショップの場合は無制限扱い）
  - `items`: 陳列商品リスト (`ShopItemListing[]`)
    - `id`: 商品スロットID
    - `itemId`: アイテム個体ID
    - `itemTypeId`: アイテム種別ID
    - `name`: 商品名
    - `description`: アイテム説明
    - `price`: 現在の販売価格（ゴールド）
    - `baseMarketPrice`: 基本市場価格（ゴールド）
    - `stockAmount`: 現在の在庫数
    - `itemDetails`: `InventoryItem` 詳細パラメータ
  - `appraisalFeeRate`: 鑑定料倍率（標準 1.0）

### 5.2 鑑定料の計算式 (Appraisal Fee Calculation Formula)
未識別アイテムの鑑定を依頼する際の費用は以下の計算式に従います。
- **計算式**: `鑑定料 = 50 + (アイテムの Tier * 50)`
  - Tier 1: 100 Gold
  - Tier 2: 150 Gold
  - Tier 3: 200 Gold
- 呪われた状態（Cursed）の未識別品であっても鑑定料は一律です。

### 5.3 商品の補充・更新メカニズム (Restock Rules)
- **システムショップ (System Shop)**:
  - プレイヤーが新しい階層（フロア）に到達するごとに、または前回の補充から **300 ティック** が経過するごとに陳列アイテム（3 〜 6 スロット）が自動で再抽選・補充（Restock）されます。
- **管理者ショップ (Admin Shop)**:
  - 管理者が「倉庫（[倉庫システム](Warehouse-System.md)）」から新しいアイテムを陳列追加したタイミング、または設定価格を更新したタイミングでリアルタイムにカタログが更新されます。

### 5.4 ショップ取引のイベントログ記録 (`shop_transaction`)
プレイヤーが購入、売却、または鑑定を実行した際、[イベントログ詳細仕様](../implementation/Event-Log-Schemas.md) の `shop_transaction` イベントとしてログが記録されます。

## 6. 経済への影響

### 6.1 サーキュレーション制限
- [機能仕様書](Functional-Specification.md) に基づき、貴重なアイテムには世界内の存在上限が設定されています。
- ショップでの売買は、この流通カウントに即座に反映されます。

### 6.2 世界間貿易
- 他の世界から持ち込まれたアイテムがショップで売却されることで、その世界内での希少価値が変動します。
