# Game-Balance-System

## 1. 概要
本ドキュメントは、非対称マルチプレイヤー型ローグライクゲームである RogueF において、プレイヤー（探索者）とダンジョン管理者、および侵入者（PKer）の三者間のパワーバランスを適切に保ち、「手応えのある、かつ不条理でない」快適なゲームプレイ環境を提供するための**ゲームバランス調整システムおよび管理者向けライブバランス調整コンソール**の仕様を定義します。

本システムは、コードの再ビルドを必要とせず、稼働中のゲームサーバー上の各種バランスパラメーターをリアルタイムに変更・反映できる仕組み（ライブチューニング）と、ゲームバランスの良し悪しを客観的に評価するためのプレイデータ収集（テレメトリ）を特徴としています。

---

## 2. 動的バランス調整パラメーター (BalanceConfig)

ライブ調整コンソールを介してリアルタイムに編集可能なパラメーター群を定義します。これらの設定は、バックエンドのメモリ上で保持され、更新された瞬間にすべての稼働中ゲームセッションに動的に反映されます。

### 2.1 出現密度・確率パラメーター
ダンジョン内の自然発生リソース、敵モンスター、および罠の出現率を調整します。

- **`baseItemSpawnLimit` (基準アイテム出現数)**:
  - 1階層あたりに自然発生するアイテム数の範囲。標準値: `5` 〜 `12`（[ドロップ品・出現システム](Loot-and-Spawn-System.md) 参照）。
- **`baseGoldSpawnLimit` (基準ゴールド出現数)**:
  - 1階層あたりに自然発生するゴールド山の数。標準値: `3` 〜 `8`。
- **`monsterSpawnInterval` (モンスター再出現間隔)**:
  - 新しい野生モンスターが追加で湧くプレイヤーのアクション数。標準値: `50` アクション。
- **`monsterFloorLimit` (階層最大モンスター同時生存数)**:
  - 1階層あたりの同時生存モンスター数上限。標準値: `20`（モンスターハウス階層は `40`）。

### 2.2 スケーリング係数
階層の進展に伴うモンスターの強さ、獲得経験値、およびゴールドの成長曲線を制御します。

- **`expGainMultiplier` (獲得経験値倍率)**:
  - 全てのモンスター撃破および階層突破時に得られる経験値に対する大域的な乗算補正値。標準値: `1.0`。
- **`goldGainMultiplier` (獲得ゴールド倍率)**:
  - フィールド拾得およびドロップゴールドに対する大域的な乗算補正値。標準値: `1.0`。
- **`monsterStatScalingFactor` (モンスター成長倍率)**:
  - 階層に応じたモンスターのステータス上昇にかける係数。標準値: `1.0`。
- **`strayLevelOffset` (Strayモードレベル補正)**:
  - PKerがStrayモードで侵入する際のモンスターレベルスケーリングにかけるレベル補正。標準値: `0`（[PKシステム](PK-System.md) 参照）。

### 2.3 経済・循環定数
ゲーム内のアイテム循環および施設利用にかかるコストのバランスを調整します。

- **`baseShopBuybackRate` (ショップ基本買取率)**:
  - 管理者ショップでプレイヤーからアイテムを買い取る際、基本価値に対する買取比率。標準値: `0.3` (30%)（[ショップシステム](Shop-System.md) 参照）。
- **`circulationLimitModifier` (流通上限補正)**:
  - サーキュレーション制限の閾値を全体的に増減させる補正係数。標準値: `1.0`。
- **`constructionCostMultiplier` (建築・拡張コスト倍率)**:
  - 階層追加や施設設置に消費するゴールド・素材のコストに掛ける係数。標準値: `1.0`（[建築システム](Construction-System.md) 参照）。

### 2.4 マッチング範囲パラメーター
PKマッチングにおけるターゲット選定ルールを微調整します。

- **`pkMatchLevelRange` (PKマッチングレベル幅)**:
  - 侵入対象プレイヤーを検索する際の、自身のレベルに対する許容レベル誤差幅。標準値: `10`（レベル ±10 以内）。
- **`pkProtectionCooldownMinutes` (PK保護クールダウン)**:
  - PKに遭遇したプレイヤーが再侵入を受けない保護（免疫）時間。標準値: `20`（分）。

## 3. リアルタイム・バランス調整コンソール

開発チームまたは世界の管理者がゲームバランスを調整するためのインターフェースおよびサーバーサイドの動作ロジックです。

### 3.1 コンソールの役割
- **パラメータの動的変更**:
  - 管理画面（またはデザイナー用コンソール）から上記の `BalanceConfig` の値を書き換えることができます。
- **即時ブロードキャスト**:
  - 変更が保存されると、バックエンドは **SSE (Server-Sent Events)** または WebSockets を利用し、すべてのアクティブなクライアントおよびゲームループインスタンスに対して最新の構成を即座に送信（ブロードキャスト）します。
  - クライアント側（プレイヤーやモンスター）は、リロードを行うことなく次のアクションやドロップ判定から新しいパラメーターが適用されます。

## 4. バランステレメトリとデータ収集 (BalanceTelemetry)

「プレイ感覚」や「面白さ」を定量的なデータから評価するため、バックエンドはセッション情報を常に集計し、テレメトリデータとしてコンソールへ提供します。

### 4.1 収集される主要メトリクス

- **`deathHeatmap` (死亡ヒートマップ)**:
  - プレイヤーが死亡した階層、座標、および原因（モンスター名、トラップID、飢餓、PKer、環境効果）をマッピングし、"即死トラップ部屋" などの不条理な難所を検出します。
- **`itemUsageStats` (アイテム利用統計)**:
  - 各アイテムの消費率、売却率、合成での使用頻度を追跡し、過小評価・過大評価されている（インバランシングな）アイテムを特定します。
- **`pkWinRatio` (PK勝率)**:
  - PKer vs 探索者の勝率、および平均戦闘時間。勝率がどちらかに著しく偏っている場合（例：PKer勝率が80%を超えるなど）、マッチング範囲やStrayモード時のレベル補正、またはPKerの行動制限ルールを動的に調整するトリガーとします。
- **`matchmakingFailureRate` (マッチング失敗率)**:
  - PKerがマッチングを試みて、マッチングが成立しなかった、またはキュー内でタイムアウトした比率。

## 5. 人間が主導すべき調整基準 (Human Play-feel Tuning)

本プロジェクトにおいて、AI による数値的な最適化だけでなく、**人間が「プレイ感覚（手触り）」や「面白さ」を基準として最終決定を下すべき項目**のガイドラインです。

### 5.1 緊張感と疲労感のバランス
- **移動と空腹感の手触り**:
  - 敏捷性によるアクションインターバルの変化が、操作上の「心地よさ」につながっているかを評価します。
  - 敏捷性が高くインターバルが短いプレイヤーが、テンポが早すぎて状況把握が困難（疲労感が勝る）になっていないかを実際にテストプレイで検証します。
- **不条理さの排除**:
  - テレメトリの「死亡ヒートマップ」で特定箇所に死亡が集中している場合、それが「挑戦しがいのある難易度」なのか、それとも「避ける方法のない不条理な即死」なのかを人間が判断し、出現密度やトラップダメージを減算します。

### 5.2 経済の健全性（インフレとデフレの調整）
- **ゴールド価値の維持**:
  - プレイヤーが拠点とダンジョンを往復する中で、ゴールドが過剰に余る（インフレ）か、常に枯渇して建築システムが全く楽しめない（デフレ）かを判断します。
  - ショップの基本買取率や建築コスト倍率をライブコンソールで微調整し、"ちょうどよくモチベーションが維持できる" 循環線を人間が設計します。

### 5.3 派閥間の駆け引き
- **PK遭遇頻度の手ざわり**:
  - PKerの侵入が頻発しすぎて探索者が安心してダンジョンを遊べない場合、PK保護クールダウン（`pkProtectionCooldownMinutes`）を引き上げ、逆に過疎化している場合はマッチング幅を広げることで、適度な「ハラハラ感」を人間が維持します。
