## 3. 今後の課題（実装優先順位）
1. **UI/UXコンポーネントの実装と拡張**: 策定された [UI・UX設計](UI-UX-Design.md) に基づき、新機能（宝箱開封、釣り、祭壇、称号、クエスト表示など）の各種操作パネル、エモート・スタンプ送受信パレットをクライアント画面に組み込む。
2. **バックエンドデータモデルとの完全な統合**: 定義済みの `Player` データモデル（[実装詳細](../implementation/Implementation-Details.md) 参照）に基づき、拡張された各種パラメータ（釣りレベル、アンロック済み称号、称号表示、アクティブタイトル、天候状態等）の取得・更新処理の実装。
3. **フロントエンド制御ロジックの調整**: 天候やバイオーム、特定の装備や特性（`flying`, `aquatic` 等）に応じたクライアント側の視覚的演出、およびクールタイム・アクションインターバル表示倍率の動的制御。
4. **管理用画面・介入コンポーネントの拡充**: `admin` 配下の各種コンポーネントにおいて、配置施設（彫像、祭壇、釣り堀等）の設置・設定画面、および遠征隊編成・進捗管理UI、リアルタイム介入コマンドパネルの実装。
5. **リアルタイム同期とSSE通信の最適化**: 複数プレイヤーや乱入したPKer（モンスター）の現在位置・演出情報のSSEリアルタイム購読、およびイベントログ表示の快適化。

## 4. 完了済みの課題 (History)

### 2026年3月
- **仕様の明確化とステータス定義の追加**: `luck`（運）ステータスの追加、レベルアップ時の成長法則（HP/運）の確定、トラップ探索・解除の計算式策定、およびPK敗北時のペナルティ内容の具体化。
- **ドキュメント間のデータモデル不整合の修正**: 満腹度、戦闘ステータス、インベントリ、状態異常の欠落および Angular/TypeScript バージョン表記の不整合を修正。
- **ユニットテストの安定化**: `HttpClientModule` や `Router` の欠落、タイトル不一致などの問題を修正し、テストが正常にパスするように改善。
- **仕様の具体化と欠落情報の追加**: モンスター形態の成長システム、ダンジョン建設容量の計算式、および各種システムの曖昧な数値（毒ダメージ、AI視界、ショップ価格帯等）を確定。
- **アイテム・数値仕様の補完**: 全アイテムのマスターリスト作成、繁殖コストと孵化時間の確定、およびモンスター形態への `luck` ステータスの反映。

### 2026年4月
- **上位装備の仕様追加および合成成功率の確定**: 不足していた Tier 3 武器（魔法の剣、エルフの弓）および Tier 2 弓の仕様を追加。また、合成システムにおける高位装備の基本成功率を 70% に確定。

### 2026年7月
- **バイオーム・環境およびモンスター遠征システムの策定**: 洞窟・森林・氷雪・溶岩バイオーム特有の補正効果、および所有モンスターを派遣する自動遠征機能（コスト・報酬・相性ボーナス・倉庫制限等）の設計。
- **オーディオおよびBGMシステム設計の統合**: 音量設定（Master/BGM/SE）、状況（拠点/ダンジョン/バイオーム/ピンチ/PK遭遇）に応じた動的BGM遷移、SE空間減衰、および同時再生数制限の仕様策定。

### 2026年8月
- **追加サブシステムの包括的設計完了**:
  - **宝箱・鍵システム**: 開錠・破壊・ミミック看破等のメカニズム構築。
  - **釣りシステム**: 釣竿、エサ、釣獲物の定義、および管理者設置釣り堀仕様。
  - **彫像および祭壇システム**: 配置施設（Statue/Altar）がもたらす周辺バフ・デバフ、神の祝福・神罰の策定。
  - **称号および実績システム**: 解除条件、装備時バフ、およびNPC会話・表示影響。
  - **クエストシステム**: 探索者・管理者・PKerロール毎のクエスト、および詳細な報酬マスターリスト定義。
  - **昼夜・天候システム**: 120ティック周期の時間経過、天候テーブル、新デバフ（冷気/熱気）、および他機能（釣り・戦闘等）への動的相乗効果。
  - **ゲームバランスシステムおよび通信用データモデル補完**: テレメトリ自動収集（死亡、アイテム消費、PK勝率等）、管理者用ライブチューニング、および拡張された全イベントログスキーマとTypeScript型定義（`DungeonEvent`等）の同期。
  - **リプレイ・観戦システム**: SSEによるリアルタイムダンジョン観戦（全開/限定視界・声援送受信）、ティック単位の差分ログを用いた軽量リプレイ（`ReplayHeader`, `ReplayFrame`, `ReplayData`, `SpectatorSession`）、再生コントロールUI、および殿堂入り・トラストネットワーク共有の仕様策定。
  - **倉庫システム拡張およびリソース操作APIの補完**: 管理者ストックアイテム利用規準の確定、倉庫容量拡張（`POST /api/admin/warehouse/expand`）およびリソース操作用API仕様とデータモデル（`WarehouseExpandRequest`, `WarehouseExpandResult`）の整備。
  - **UI/UX設計仕様の全サブシステム補完**: 観戦・リプレイ操作画面、オーディオ設定パネル、ゲームバランス・テレメトリ調整画面、および倉庫枠拡張ダイアログのUIコンポーネント階層・レイアウト・インタラクション詳細仕様を `UI-UX-Design.md` に追加統合。
  - **インベントリ整理・スタック制御仕様およびソート・入れ替えAPI定義の補完**: インベントリ内アイテムの自動整列（ソート）における 5 段階優先度ルール、99 個上限のスタック統合・分割ロジック、`InventoryItem` 完全データモデル補完、ならびに操作用 REST API (`PUT /api/player/{userId}/inventory/sort`, `PUT /api/player/{userId}/inventory/swap`) と TypeScript 型定義 (`InventorySortRequest`, `InventorySwapRequest`) の策定・追加。
  - **郵便受け・プレゼントシステム仕様の策定およびデータモデル・API定義の補完**: 運営通知、シーズンランキング報酬、ダンジョンクリア時の超過ドロップ保護に関するメール分類、30日間有効期限・自動整理ロジック、TypeScriptデータ型（`MailMessage`, `MailAttachment`, `MailClaimResult`）、REST API (`GET/POST/DELETE`)、インベントリ超過時の拠点倉庫自動転送、および拠点郵便受けモーダル（UI/UX設計）の策定・統合。
