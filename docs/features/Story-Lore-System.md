# Story-Lore-System

## 1. 概要
ストーリー・世界観システムは、RogueF の世界設定（Lore）をプレイヤーに提示し、ゲームへの没入感を高めるための仕組みです。プレイヤーは探索やNPCとの対話を通じて、失われた記憶やダンジョンの真実、世界が「フロンティア」と「マイ・ダンジョン」に分かれている理由を解き明かしていきます。

## 2. 背景設定・世界観

### 2.1 世界の創生と「コア」の暴走
かつて世界は一つの調和された大地でしたが、「大いなるコア（The Great Core）」の暴走により、世界は無数の「断片世界（Dungeons）」へと引き裂かれました。
- **フロンティア（Frontier）**: 誰も管理していない野生の断片世界。資源が豊かですが、凶暴な「野生モンスター」がはびこっています。
- **マイ・ダンジョン（My Dungeon）**: プレイヤー自身が「管理者（Administrator）」として再構築した断片世界。他の世界の管理者や探索者とつながることで、経済や流通が機能しています。

### 2.2 二つの役割（探索者と管理者）
すべての人は、自らの世界を守り育てる**「管理者」**の血を引いていますが、同時に「コア」の秘密を暴くために他の断片世界を旅する**「探索者」**でもあります。
- この二重性が、自らのダンジョンを拡張しながら、他者のダンジョンへと挑み、時には「PKer（乱入者）」として競い合う RogueF のゲームサイクルの根底にあります。詳細は **[機能仕様書](Functional-Specification.md)** を参照してください。

## 3. 解放メカニズム (Unlocking Mechanisms)
ストーリーや背景設定の断片（Lore Record）は、探索や拠点での活動を通じて**永続的にアンロック**され、プレイヤーの「ジャーナル」に記録されます。

### 3.1 探索中の発見
- **古文書（Old Document）の拾得**: ダンジョン内の宝箱や、隠し部屋（[ダンジョン生成システム](Dungeon-Generation-System.md) 参照）に稀に出現する「古文書」や「碑文」を読むことで解放されます。
- **ボスの撃破**: 各エリアのボスモンスターを初めて撃破した際に、そのエリアに関する歴史や背景ストーリーが解放されます。

### 3.2 拠点での解放
- **NPCとの親密度上昇**: 拠点の各施設（[拠点システム](Base-System.md) 参照）にいるNPCと会話を重ねたり、特定のクエスト（資材やゴールドの納品）を達成することで解放されます。
- **累計実績の達成**: 「累計クリア回数」「累計捕獲モンスター数」などのマイルストーンを達成した際に解放されます。

## 4. NPCダイアログシステム (Dynamic NPC Dialogues)
拠点やダンジョン内に配置されたNPCは、プレイヤーの状況や解放されたLoreに応じて**動的に会話内容を変化**させます。

### 4.1 会話の選択基準
会話発生時、以下の優先度に従ってダイアログが選定されます。
1.  **チュートリアル・緊急クエスト会話**: 未完了の重要イベントがある場合に最優先で発生。
2.  **特殊ダイアログ**: 特定のLoreが解放されている、または特定の「装備/称号」を所持している場合に発生。
3.  **エリア・階層クリア進行度ダイアログ**: プレイヤーの現在最高到達階層に応じた会話。
4.  **通常会話**: 季節、時間、またはランダムで選択される基本的な会話。

### 4.2 セリフの構成例
- **初期状態のNPC商人**:「ここはマイ・ダンジョン。あなたが管理者となる場所。まずはフロンティアに挑んで、資材を集めてくるのよ。」
- **特定の古文書（Lore ID: `ancient_core_01`）解放後**:「…コアの設計図を読んだの？まさか、あの時の大暴走が『意図的』に引き起こされたものだなんて、考えたくもないわね…」

## 5. UIジャーナル仕様 (UI Journal Specifications)
解放されたストーリーや背景設定を、プレイヤーがいつでも読み返せるためのUIシステムです。

- **ジャーナル画面（図解は [UI・UX設計](UI-UX-Design.md) 参照）**:
    - **カテゴリ分類**: 「歴史（History）」「人物（Biography）」「ダンジョンの謎（Dungeon Secret）」「NPCの日記（NPC Diary）」の4つのカテゴリにソート可能です。
    - **解放率の表示**: 全体、およびカテゴリごとの「解放率（%）」を画面上部に表示し、収集要素としてのモチベーションを高めます。
    - **未解放項目のヒント**: 未解放の項目には「？？？」と表示されますが、選択すると「入手方法のヒント（例：3階のボスを撃退する、等）」が薄く表示されます。

## 6. 技術データ構造 (Technical Data Structures)
プレイヤーのストーリー進行状況およびダイアログ制御に必要なデータモデルを定義します。

### 6.1 Playerデータモデルの拡張
プレイヤーのストーリー進行状況を永続化するため、**[Playerデータモデル](../@types/player.d.ts)** に以下のプロパティを追加します。

```typescript
// Playerクラス/インターフェースに追加されるプロパティ
unlockedLoreIds?: string[]; // 解放されたLoreのIDリスト
```

### 6.2 LoreEntry（ロアエントリー）インターフェース
```typescript
interface LoreEntry {
  id: string;                                                          // ユニークID (例: 'ancient_core_01')
  title: string;                                                       // タイトル (例: '大いなるコアの記録 1')
  category: 'history' | 'biography' | 'dungeon_secret' | 'npc_diary';  // カテゴリ
  unlockedAt?: Date;                                                   // 解放日時
  hintMessage: string;                                                 // 未解放時のヒントメッセージ
  content: string[];                                                   // 本文の段落リスト
}
```

### 6.3 NpcDialogue（NPC会話ライン）インターフェース
```typescript
interface NpcDialogue {
  id: string;                     // ダイアログID
  npcId: string;                  // 対象 of NPC ID (例: 'merchant_anna')
  triggerCondition: {
    requiredPlayerLevel?: number; // 必要なプレイヤーレベル
    requiredLoreId?: string;      // 必要な解放済みLore ID
    requiredFloor?: number;       // 必要な到達階層
  };
  dialogueLines: string[];        // 会話テキスト
}
```
